# Lion Hills — быстрая дока

Одностраничный промо-лендинг ЖК **Lion Hills** (виллы и пентхаусы, Лісники, Київ). Тексты на **украинском** (`lang="uk"`). Статика без сборки: открывается `index.html` напрямую или любым static-сервером. Git-репозиторий (ветка `main`), деплой — lionhillsweb.vercel.app.

## Попап-квиз `.quiz`
Разметка после `.main_section` (вне трансформированных предков), стили — блок «Request popup» в `style.css` + мобилка в конце, логика — `scripts.js`. Открывается, когда верх `.ready_box` блока «Готовність комплексу 2027» (`[data-quiz-trigger]`) проходит 60% высоты экрана. Раз за визит (`sessionStorage` `lh-quiz-seen`), после отправки больше никогда (`localStorage` `lh-quiz-sent`); `?quiz` в адресе сбрасывает обе отметки (для проверки). Шаги: тип (фото: `villa5.png`, `kraevid.webp`, `Build/webp/DJI_0346`) → способ связи (изначально ничего не выбрано) → имя + телефон → «Дякуємо», через 3.5с закрывается. Автоперехода нет: «→» активна только после выбора. Код страны — выпадающий список (Україна + Європа, массив `countries` в `scripts.js`, флаги SVG из `flag-icons@7.2.3` на jsDelivr), скрытое поле `code`; маска `XX XXX XXXX` только у Украины, у остальных цифры по 3, 6–12 цифр. Мобилка: попап во весь экран с отступом 12px (+ safe-area), карточки — широкие полосы, варианты связи столбиком; код страны — нативный `<select>` (`.quiz_code_select`, невидимый поверх кнопки, флаги эмодзи), на десктопе свой список (эмодзи-флаги Windows не рисует); шаг 3 прижат кверху, чтобы поля не уходили под клавиатуру; Enter в имени → телефон. Оверлей высотой `100lvh` (под нижней панелью Safari 26 иначе просвечивает незатемнённая страница). Отправка — Web3Forms (`sendForm()` в `scripts.js`, ключ `WEB3FORMS_KEY`, ловушка `botcheck`; названия полей письма по-английски — Form, Property type, Contact method, Name, Phone с кодом, Country: кириллицу в ключах Web3Forms превращает в кракозябры, значения остаются украинскими); «Надсилаємо…» на кнопке, при ошибке «Помилка, спробуйте ще» и данные остаются, `lh-quiz-sent` ставится только после успешной отправки. Пока открыт: `html.quiz-open` (overflow hidden) + `lenis.stop()`; закрытый — `display: none` через `presence()`.

## Интро (лоадер)
Две версии, обе в `index.html`; сейчас везде **v2** (константа `LOADER` в начале `animations.js`), другая сразу удаляется. Общее: рисунок идёт **по времени** (`DRAW_DURATION` = max(`MIN_LOADER` 3с, `minLap` версии), одинаково на любой сети; `counter.v` 0..100), метка `reveal` и шторка hero. После рисунка и `done()` версии — `waitCritical()`: если `criticalReady` ещё нет, через 300мс лоадеру ставится `.is-waiting` и под фразой мигает «завантаження…» (`.loader_v2_status` внутри `.loader_v2_sub`, абсолютом — лого не сдвигается; внешний span гаснет за 0.3с, внутренний мигает), когда готово — надпись гаснет и шторка. На быстрой сети/из кэша надпись не появляется.
- **v2 (десктоп + мобилка)** — `#loader-v2` (`loaderV2()`): фон `#374A46`, инлайн-SVG орнамента из `media/pattern light upd 2.svg` (viewBox 1647×1088, 35 `<line>` — убраны 3 линии, что шли через лого; первая точка — нижний конец; `pattern.svg` / `pattern light.svg` — старая версия). Сначала проявляются горизонтали (в первые `H_PHASE` = 25% прогресса), потом остальные линии по одной в случайном порядке (`Math.random`, каждый раз по-новому): JS создаёт каждой свой `linearGradient` (userSpaceOnUse) как stroke, мягкий край (`BAND` = 0.6 длины) бежит вдоль линии от первой точки ко второй, одна линия = `DUR` 0.3 всего рисунка. До JS линии скрыты (`stroke: none` в CSS, JS ставит инлайн `stroke`). Орнамент полупрозрачный (`opacity: 0.4` на `.loader_pattern`). Рисование 4.5с (`minLap`), шторка стартует не раньше ~5с. На 60% рисования (`BRAND_AT`) по центру из blur (на тач-устройствах, вкл. iPad, — `opacity` + подъём, как на мобилке: `filter` на iPad — вероятная причина цветной полосы за лого; на десктопе после твина `clearProps: 'filter'`) выходит белое лого `.loader_v2_logo`, следом фраза «Життя на висоті» (`.loader_v2_phrase`, opacity 0.75) — оба в `.loader_v2_brand`, таймлайн `brandIn`; `done()` ждёт его конца + 0.4с, затем шторка hero; орнамент и лого чуть уезжают вверх. У каждой версии свой `done()` — что происходит между 100% и шторкой (v1: пауза 0.3с).
- v2 на мобилке: в масштабе телефона 3 ряда паттерна закрывают ~60% высоты, поэтому JS дорисовывает ряды (копия нижнего над верхним, верхнего под нижним, и ещё копия среднего ниже; совпадающие горизонтали не дублируются) и ставит `viewBox="5 -319 1569 1724"` — 5 рядов (`-34 -362 1647 1810`) приближены на 5% вокруг того же центра, чтобы верхняя горизонталь ушла за верх экрана (иначе белая линия по самому верху страницы), по центру пустая ячейка среднего ряда (x 509..1071) с лого. Лоадер на мобилке высотой как hero (`100lvh + 5vh + 20px`): нижняя панель Safari 26 плавает над страницей ниже 100lvh, там просвечивала страница. Орнамент и лого центрируются по `100svh` (в Chrome iOS при `lvh` лого было ниже центра), SVG с `overflow: visible` дорисовывает 6-й ряд ниже своего бокса. Лого 170px, фраза 15px; появление без анимации `filter` (iOS), а `opacity` + подъём.
- **v1 (выключен)** — `#loader` (`loaderV1()`), описание ниже; был мобильным.

v1: серый экран `#eaeaea`: в центре из blur выходит лого `.loader_logo` и уходит, затем на его месте фраза «Життя на висоті. Лісники, Київ» собирается по частям в одну строку (мобилка: все 3 части сменяют друг друга по одной, без точки), линия `.loader_frame` едет по краю экрана + счётчик %. Затем шторка снизу вверх с параллаксом фото (см. «Шторка и LCP» ниже), следом строки заголовка (SplitText с маской), подзаголовок/хедер, кнопка. Линия и % теперь идут по времени, как у v2 (раньше — за `window.loadProgress()`); шторка — после 100% (+0.3с) и `criticalReady`. В конце лоадер удаляется, снимается `is-loading`, стартует Lenis. Без GSAP или при reduced-motion лоадера нет (`bail()`).
- Мобилка: «разблюр» без анимации `filter` (в iOS Safari рывком становился чётким): `intro()` клонирует каждую `.loader_part` в `.loader_ghost` (статичный `blur(5px)`, светлый цвет, своя композит-плоскость), и копия кроссфейдится в чёткий текст — анимируется только `opacity`. Обе прозрачности ведёт один твин `focus()` (прогресс `p`: текст `p^1.6`, копия `min(1,3p)·(1−p)`), `immediateRender: false` обязателен — иначе «out»-твин сразу показывает часть. Десктоп — как раньше, `filter: blur()`.
- Пауза таймлайна сделана через `tl.call` + `tl.pause()`: `addPause` с колбэком в GSAP 3.13 колбэк не вызывал.
- Headless Chrome с `--virtual-time-budget` не годится для проверки таймлайна: виртуальное время бежит быстрее кадров GSAP.

## Шторка и LCP
Hero лежит **под** лоадером и нарисован с самого начала; `addHero()` в `animations.js` обрезает сам лоадер (`clip-path: inset(0 0 Npx 0)`) снизу вверх по той же линии, по которой раньше открывался hero (`inset(100%)→0` по высоте hero, 1.6с `power2.inOut`) — на вид как раньше. Заголовок hero не скрыт `js-anim`: это LCP-элемент (полноэкранное фото hero Chrome как кандидата LCP не считает — «фон»), он рисуется сразу под непрозрачным лоадером, а при старте шторки SplitText прячет строки под маски и выводит их как раньше. LCP ~7.8с → время загрузки шрифта. Старый вариант (hero поверх лоадера, `html.is-loading .hero { z-index: 101; clip-path }`) — `variants/original loader/`.

## Загрузка медиа
Все `<img>`/`<video>` ниже hero — с `data-src` вместо `src` (без `src` новые медиа не добавлять: загрузит только код из `scripts.js`, блок «Media loading»).
1. **Критичное** (грузится во время лоадера, параллельно) — `<link rel="preload">` в `<head>`: Aeonik Pro Regular + Medium, `hero2_compressed.jpg` / на мобилке `vert hero mob new 2.jpg` (через `media`); плюс `data-load="critical"`: `Bird_Update.mp4`, 1-й слайд «Концепції» (`Location.webm`), 1-я карточка клабхауса (SPA), обложки 5 сторис вилл (на десктопе WebP: `villa1.webp`… `villa 5 new.webp`; картинки ещё и `decode()`). Видео — до первого кадра (`loadeddata`), на тач-устройствах (`isTouch`: `(hover: none), (pointer: coarse)` или `MacIntel` + тач = iPad) — до `loadedmetadata`: iOS/iPadOS не буферизует незапущенные видео. `isMobile` (ширина) по-прежнему решает, какие файлы (`data-src-mobile`) и вёрстка; iPad получает десктопные файлы. `window.criticalReady` (+ `window.loadProgress()` 0..1, лоадером больше не используется), общий лимит `CRITICAL_MAX` = 9с. При `saveData` / 2g (`isSlowNet`) critical = только шрифты + hero, остальное — в очередь. Скрипты (GSAP, Lenis, `scripts.js`, `animations.js`) — в `<head>` с `defer fetchpriority="high"` + `preconnect` к cdnjs/jsdelivr: рисунок лоадера стартует раньше (у `defer` без `fetchpriority` приоритет ниже фото hero и шрифтов — было позже).
   - На мобилке `data-load-mobile` переопределяет `data-load` (`loadGroup()` в `scripts.js`): критичные видео там `queue`, критичное = шрифты + `vert hero mob new 2.jpg` + обложки 5 вилл (без `data-load-mobile`: при быстром скролле были чёрные баннеры, пока они грузились). Мобильные обложки вилл 1 и 3–5 — JPG-копии (`…compressed.jpg`, 1800px по высоте, q82; PNG-оригиналы рядом не подключены; вилла 1 — `villa1_nobalcon compressed.jpg`). Причина: iOS не буферизует незапущенные видео, лоадер висел на ~88% до `CRITICAL_MAX`. Очередь и подгрузка блоков (`near`) на мобилке ждут `loaderDone` — событие `loader:done` из `animations.js` (старт шторки или `bail()`), чтобы загрузка не дёргала текст лоадера.
2. **Очередь** — `data-load="queue"`, в порядке страницы после `criticalReady`, по `QUEUE_SLOTS` = 3 файла одновременно (`loadInTurn()`): 1-е видео галереи вилл (`terrace.webm`), `build1`, первый слайд остальных `.gallery` / `.carousel`, `build2`. Слот берёт следующий файл после `loadeddata`/`load` (тач — `loadedmetadata`; или 10с).
3. **Остальное** — слайды `.gallery`/`.carousel` целиком, когда блок в ~1 экране (`rootMargin: 100%`); `.stories` сами грузят текущий + следующий слайд (с `preload='auto'`), когда рядом; плюс когда первая вилла в ~1 экране, все слайды всех вилл грузятся фоном по одному по порядку. Клик по вкладке галереи подгружает её сразу. Галерея заранее буферизует следующий слайд (`primeNext()`: `preload='auto'` вместо `metadata` из разметки), но не раньше `criticalReady`.
- Все MP4 — с `moov` в начале файла (faststart): с `moov` в конце видео не стартует, пока не скачано целиком (так было у build1/2, sklo, architrecture и мобильных Build Ready / Build 27 / windows_mob / Villa 2). Новые MP4 проверять; переставить без перекодирования — `ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4`.
- Постеры: у каждого `<video>` есть `data-poster` (и `data-poster-mobile` для `data-src-mobile`) — первый кадр в WebP рядом с видео (`<имя>.poster.webp`, десктоп до 1600px, мобилка до 800px). `loadMedia()` ставит `poster` до `src`, поэтому пока видео грузится, виден кадр, а не чёрный/белый блок. Критичное видео (Bird) лоадер ждёт только по постеру, сам файл открывает очередь. Новое видео — сразу с постером: `ffmpeg -i in.mp4 -frames:v 1 -vf "scale='min(1600,iw)':-2" -c:v libwebp -quality 72 out.poster.webp`.
- Видео сжаты ffmpeg (H.264, без звука, ≤30 fps, десктоп до 1920px в ширину, мобильные вертикальные 810px; CRF подобран по VMAF ≥ 95.5 к исходнику), WebM заменены на MP4 (iPad/старые iOS). Картинки — WebP (фото q80, планировки с прозрачностью q88). Исходники — в истории git.
- Inter (Google Fonts) удалён — не использовался. PP Hatton не в preload (только лого).

## Система анимаций (`data-anim`)
- `hero-title`, `hero-fade`, `hero-header` — анимирует `intro()`
- `lines` — заголовки; обычный fade-up, как `fade`
- `scrub` — абзац «заливается» по словам при скролле
- `fade` / `fade-only` — появление с подъёмом / без
- `stagger` — дети контейнера по очереди
- `count` — цифры в `.lot_main` / `.lot_terrace` считаются от 0
- Скрытие до старта GSAP через `html.js-anim` (кроме заголовка hero — см. «Шторка и LCP»); инлайн-скрипт ставит `js-anim` и `is-loading` вместе, только если нет reduced-motion.
- `footerReveal()` — scrub: футер расширяется (`--inset` 2.5vw→0.5vw, мобилка 12px→6px) и съезжает вниз, открывая `.outro`. CSS по умолчанию = конечное состояние.
- `setupSnap()` — пошаговый скролл по `.types .stories`, только desktop с мышью и Lenis (на Mac его нет).

## Конвенции
- Классы BEM-подобные через подчёркивание: `block_element` (`gallery_tab`, `stories_seg`), состояния `active`, `done`, `is-open`, `is-visible`.
